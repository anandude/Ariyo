# Neon Port Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the dead Supabase backend of the Ariyo Vite/React app with Neon Auth, Neon Data API, and Neon Object Storage so the app works again.

**Architecture:** Browser talks to Neon Data API (PostgREST) directly using `@neondatabase/neon-js`; auth via Neon Auth's Better Auth client; profile images uploaded through a presigned URL minted by a Neon Function into the `profile-images` bucket. RLS on `public.people` enforces per-user isolation.

**Tech Stack:** Vite 5, React 18, TypeScript, pnpm, `@neondatabase/neon-js`, `@neondatabase/auth`, files-sdk, AWS S3 SDK (presigner), Neon CLI 8.0.6.

**Spec:** `docs/superpowers/specs/2026-10-04-neon-port-design.md`

Note: this repo has no test runner configured. Each task's verification is
`npx tsc --noEmit -p tsconfig.app.json`, `npm run lint`, `npm run build`,
plus the browser smoke steps in Task 8. Do not add a test framework.

## Global Constraints

- Preserve existing features and UI in `src/pages` and `src/components`.
- No Supabase data import; old project is deleted.
- Keep Vercel deployment model (`VITE_*` env vars only in the browser).
- Auth emails use shared `auth@mail.myneon.app` SMTP for now.

## Review Focus

- RLS must isolate people per user (two-account check in Task 8).
- Presigned upload URL must be scoped to the calling user's id and reject unsigned calls.
- `image_url` stored must be publicly readable without credentials (bucket is `public_read`).
- Session must survive a page reload (Better Auth session cookie/JWT).
- All `VITE_*` env vars present in `.env.local` before `npm run dev`.

- [ ] **Step 2: Write `src/integrations/neon/client.ts`**

```ts
import { createClient } from '@neondatabase/neon-js';
import { createAuthClient } from '@neondatabase/auth';
import { BetterAuthReactAdapter } from '@neondatabase/auth/react/adapters';

const authUrl = import.meta.env.VITE_NEON_AUTH_URL;
const dataApiUrl = import.meta.env.VITE_NEON_DATA_API_URL;
if (!authUrl || !dataApiUrl) {
  throw new Error('Missing Neon environment variables. Check your .env.local');
}

export const authClient = createAuthClient(authUrl, {
  adapter: BetterAuthReactAdapter(),
});

export const client = createClient({
  dataApi: { url: dataApiUrl, getToken: async () => (await authClient.token()).data?.token },
});
```

### Task 6: Upload function + storage wiring

**Files:**
- Create: `api.ts`
- Modify: `neon.ts`
- Modify: `src/components/ImageUpload.tsx`, `src/components/ImageUploadModal.tsx`, `src/components/ProfilePictureModal.tsx`

- [ ] **Step 1: Write `api.ts`**

Default-exported web-standard handler with one route: `POST /upload`. Behavior:
- Read `Authorization: Bearer <jwt>`; verify with JWKS from `NEON_AUTH_JWKS_URL` (injected) and extract the user id (`sub`); 401 otherwise.
- Accept JSON `{ filename, contentType }`; build key `people/<userId>/<uuid>.<ext>`.
- Use files-sdk `neon` adapter (`signedUploadUrl`) with bucket `profile-images` to return `{ uploadUrl, publicUrl }` where `publicUrl = ${AWS_ENDPOINT_URL_S3}/profile-images/<key>`.
- Basic hardening: allow only image content types, cap key extension to `jpg/jpeg/png/webp/gif`.

Check the neon-functions skill (`node_modules`-adjacent `.agents/skills/neon-functions`) for the exact local dev/deploy loop (`neon dev`, `neon deploy`).
